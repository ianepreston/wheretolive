  <action>
This task validates and deploys the DAB project. The files listed under `files` may need modifications if validation or deploy fails -- they are listed as potentially modified, not necessarily modified.

**Step 1: Pre-flight catalog check**

Run: `databricks catalogs list --profile free-edition`

Verify the output contains a catalog named `workspace`. If the catalog has a DIFFERENT name (e.g., the workspace name instead of "workspace"), update the `variables.catalog.default` value in `databricks.yml` to match the actual catalog name. Also update the `catalog` variable in `notebooks/setup/verify_schema.py`.

**Step 2: Local validation**

Run: `databricks bundle validate --profile free-edition`

This must exit with code 0 and no error messages. If it fails:

- **"notebook not found" errors**: Check that notebook paths in `resources/job.yml` and `resources/pipeline.yml` are relative to the resource YAML file location (i.e., `../notebooks/...` from `resources/`). Fix paths if wrong.
- **"unknown field" errors**: Remove the offending field from the YAML. Common culprit: `serverless: true` in pipeline.yml may not be valid on free edition. Remove it if flagged.
- **"pipeline configuration" errors**: The pipeline resource may need additional fields. Check the error message and add required fields. If `catalog` or `target` fields are not supported, try removing them and setting catalog/schema via the pipeline notebook itself.
- **Variable interpolation errors**: Ensure `${var.catalog}`, `${var.schema}`, and `${resources.pipelines.medallion_pipeline.id}` use exact syntax.

Re-run `databricks bundle validate` after each fix until it passes.

**Step 3: Deploy to workspace**

Run: `databricks bundle deploy --target dev --profile free-edition`

This must complete successfully. Expected output includes resource creation/update messages. In development mode, resource names will be prefixed with `[dev <username>]` -- this is expected behavior per Research Pitfall 2.

If deploy fails:
- **Auth errors**: The `free-edition` profile must be valid. Run `databricks auth profiles` to check. If expired, this becomes a checkpoint:human-action (user must re-authenticate). Notify the user.
- **Schema creation errors**: May indicate catalog permissions issue. Try running `databricks schemas list --catalog workspace --profile free-edition` to verify catalog access.
- **Pipeline creation errors**: If `serverless: true` caused the issue, remove it from `resources/pipeline.yml` and retry. If the pipeline resource type is not supported on free edition, comment out the pipeline resource in `resources/pipeline.yml` and remove the `run_pipeline` task from `resources/job.yml`, then document in the summary that pipeline resources need to be created differently.

**Step 4: Verify schema exists**

Run: `databricks schemas list --catalog workspace --profile free-edition`

The output must contain a schema with name matching `wheretolive` (in dev mode it may be `[dev <username>]_wheretolive` or just `wheretolive` depending on how development mode handles schemas). Record the exact schema name in the plan summary.

**Step 5: Verify deployed resources**

Run: `databricks bundle summary --profile free-edition`

This should list all deployed resources: the schema, the pipeline, and the job. Verify each appears in the summary output.
